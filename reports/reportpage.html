VN30 Alpha Research — Results

Cross-sectional stock selection on the Vietnamese VN30 index, evaluated after transaction costs and Vietnam-specific execution frictions. Research framework, not a live trading system.

Bao H. G. Nguyen, Grinnell College · GitHub repository · LinkedIn

Generated 25 October 2026 from reports/tables/ · point-in-time VN30 membership · walk-forward training window 63 trading dates

Overview

Using FiinQuant daily data on the 60 stocks that were VN30 members at some point from 2016-07-26 to 2026-07-22, each counted only while it was in the index, this project asks whether 5 machine-learning models predicting each stock's 5-day return relative to the other constituents from 99 features, scored walk-forward on a 63-date training window with a 5-day purge and turned into constrained long-only portfolios, can beat an equal-weight VN30 benchmark once trading costs and the ±7% daily price limit are charged.

  1. No portfolio beats VN30 after costs: the best of the 4 optimizers, sector_diversified, turns 1.0 into 1.4850 from 2016-11-15 to 2026-07-16, while the VN30 benchmark turns it into 2.6918.
  2. A one-feature momentum rule beats all 5 trained models: ranking on trailing 10-day return and holding the top five beats every model's own top five before cost, and the strongest, elastic_net, reaches 88% of it.
  3. The momentum signal is detectable, and nothing survives the models and costs: its 95% bootstrap interval excludes zero before costs, while all 8 model-driven portfolio configurations have intervals that span zero after costs.

Full write-up: README.md · reports/methodology.md · reports/final_results.md. Every figure on this page is read from reports/tables/.

Every optimizer mode takes more risk than the VN30 benchmark for less return. All 4 are more volatile than VN30, fall further at their worst and compound more slowly, and the best Sharpe ratio among them, 0.30 for sector_diversified, is under half of VN30's 0.62.
  • Annualized return is compound: final equity raised to the power 252 ÷ trading days, minus one.
  • Annualized volatility is the standard deviation of daily returns × √252.
  • Sharpe ratio is the mean daily return ÷ its standard deviation × √252, annualized, with a risk-free rate of 0%. A risk-free rate r would lower each row by r ÷ that row's annualized volatility. It uses the arithmetic mean, so it is not annualized return divided by volatility, and it is not the per-period diagnostic Sharpe reported further down.
  • Max drawdown is the worst peak-to-trough fall of the compounded curve, as a percentage of capital.
  • Average turnover is one-way, half the sum of absolute weight changes, for the tranche rebalanced each day against the one it replaces 5 trading days earlier, averaged over all 2,418 rebalance dates. A tranche is 1/5 of capital, so 1/5 of this figure is traded across the whole portfolio each day. The VN30 basket turns over only when its constituent list changes, and carries no cost.

Data and method

Data

Daily bars from FiinQuant, a Vietnamese market-data vendor: open, high, low, close, volume, traded value, and foreign investors' buy and sell value. The canonical history holds 137,719 rows across 60 tickers from 2016-07-26 to 2026-07-22, and 74,910 of them fall on dates when the ticker was an index constituent. Raw prices drive anything tied to the printed price, such as limit bands and ceiling detection; adjusted close drives returns and labels; src/market_data_schema.py keeps the two apart.

Universe

Point-in-time VN30 membership, rebuilt from index-review announcements in config/vn30_history/, each review backed by a source in source_manifest.csv. A stock contributes rows only on dates it was in the index, so the 60 tickers include former members that were later removed or delisted, which keeps survivorship bias out of every result.

Prediction target

For each stock on each signal date: its forward return over 1, 5 and 10 trading days on adjusted close, minus the equal-weight average forward return of the other constituents that day, a leave-one-out VN30 benchmark. Production uses the 5-day target, forward_relative_return_5d; the last signal date with a complete label is 2026-07-15.

All five are used only to rank stocks within a date: portfolio construction reads the ordering, not the size, of a prediction.

Walk-forward validation

Never a random split. Each window fits on 63 consecutive trading dates, validates on 1 date and tests on 1 date, with a 5-date purge before each, so no forward label in the training window overlaps the date it is scored on. The window then steps forward 1 date, and the 5-day horizon is scored on 2,418 dates.

From signals to a portfolio

The strategy signals daily and holds for 5 trading days, so the portfolio it trades is 5 overlapping tranches: each day 1/5 of capital is rebalanced into that day's target weights and held, buy-and-hold, for 5 days. The VN30 benchmark is an equal-weight basket of the point-in-time constituents run through the same construction without cost. The charts, the Performance summary and Deployability all come from this construction, built in src/tranche_portfolio.py; the per-period tables further down average overlapping forecast periods instead.

Metric definitions

Rank IC
On each signal date, the Spearman rank correlation between the model's predicted scores and the realized forward relative returns of that day's constituents, averaged over dates. 0 means no ranking skill and 1 a perfect ranking.
Top-5 hit rate
The share of the five highest-ranked stocks whose realized forward return beats the leave-one-out benchmark, averaged over dates.
Diagnostic Sharpe
Mean per-period active return divided by its standard deviation, on overlapping forecast periods. It is per period and not annualized, so it is not comparable with the Sharpe ratio in the Performance summary.
Cumulative sum
Per-period active returns summed over every evaluated date, not compounded. Consecutive 5-day periods overlap, so each day's return is counted about five times; read it as a diagnostic, not a track record.
Active (compounded)
The product over trading days of 1 + (strategy daily return − benchmark daily return): the growth of a daily-rebalanced sleeve long the strategy and short the benchmark. Below 1.0, the strategy fell behind.
Equity ratio
Strategy final equity divided by benchmark final equity. It differs from active because compounding a difference of returns is not the ratio of compounded returns.

Deployability

Every per-period figure on this page is a mean over overlapping forecast periods, and a portfolio cannot hold an overlapping period. The strategy signals daily and holds five days, so what it trades is five overlapping tranches: one fifth of capital rebalances into each day's targets. That construction holds every phase at once and has no free parameters.

What the columns mean. Active is the compounded daily active return: the product over every trading day of 1 + (strategy return − benchmark return). It is not strategy equity divided by benchmark equity, which is why that ratio is shown beside it — compounding a difference of returns is not the same as taking a ratio of compounded returns, and the gap between the two columns is the covariance of the two legs. Strategy drawdown is the worst peak-to-trough fall of the compounded strategy equity curve, a true percentage of capital. Active drawdown is the same measure on the compounded active-return curve, so it describes the hedged sleeve rather than the account. Neither is the summed-return drawdown reported under Portfolio backtest below.

Why the training window is 63 dates

Five window sizes are measured on an identical set of 223 evaluation dates. The relationship is an inverted U, not monotonic: Rank IC peaks at 21 dates and collapses to roughly zero at 252, which is what one would expect if long windows average across market regimes that no longer apply.

63 is chosen over the Rank-IC-optimal 21 because it has the best top-5 hit rate and the only clearly positive top-5 return, and portfolio construction selects a top-N basket rather than trading the full ranking.

The sweep figure is not the production figure. This table reports Rank IC 0.028126 for the chosen 63-date window while production reports 0.033360. Both are gradient boosting on the 5-day horizon and neither is wrong. The sweep scores 223 test dates, subsampled at every tenth date and starting late enough that the 252-date window is also reachable, so that all five configurations are scored on an identical set of dates. Production walk-forward scores every date it can, 2,418 of them. A shorter, later, sparser subsample is a different sample of the same estimator, so the two figures are not required to agree.

Chart and table render from the same rows of training_window_diagnostic.csv — the chart rounds to four decimals, the table prints six, and neither carries a separate copy of the numbers. Train rows is the measured count of dataset rows falling on the first window's training dates, not the window length times 30: 126 dates measures 3,779 rather than 3,780 (1 short); 252 dates measures 7,555 rather than 7,560 (5 short). Ten dates in the dataset carry 29 constituents rather than 30, because FLC has no data for the week of 2017-01-16 and ROS none for the week of 2021-01-25, and a window spanning one of those dates is one row short for each. The shortfall is a data gap, not a counting error.

2 of 8 configurations are positive. The most conservative (normal + price_limit_aware) falls short of cost by 0.000822 per period, at a diagnostic Sharpe of −0.042. Wider diversification outperforms concentration, which is evidence that the ranking signal is weak.

Is any of this distinguishable from zero? sector_diversified + normal has mean active return 0.000225 with a 95% interval of [−0.000624, 0.001085], which spans zero. normal + price_limit_aware has mean active return −0.000822 with a 95% interval of [−0.002056, 0.000462], which spans zero. Across all 8 optimizer and execution combinations, 8 have an interval that spans zero. The interval is a 95 percent moving-block bootstrap on the mean after-cost active return, 2,000 resamples, blocked at the 5-day forecast horizon so that the overlap between consecutive period returns stays inside a block. An interval that spans zero is why no alpha claim is made here; it is not a claim that the mean is zero.

Cumulative figures in this table sum overlapping forecast-period active returns, so they are not compounded portfolio returns, and max_active_drawdown in benchmark_results.csv is a running-peak fall on that same summed series — in summed-return units, not as a percentage of capital. The Deployability table at the top of the page uses the other convention: both of its drawdown columns are peak-to-trough falls of a compounded equity curve and are genuine percentages of capital. The two conventions share no number and should not be compared.

The universe is point-in-time VN30 membership, reconstructed from verified index-review history in config/vn30_history/. Three different ticker counts appear across these outputs and all three are correct.

54 rather than 60 in the prediction file follows from point-in-time membership. Six former constituents (FLC, HAG, HCM, HNG, ITA, PPC) left the index before 2017-08-09, which is the first date that file can predict after its 252-date training warm-up, so they are correctly absent from it.

Why the prediction file carries 60 rows a date against a 30-name index. It stacks 2 models — gradient_boosting, random_forest — in one table with a model_name column, so a fully covered date carries 30 × 2 = 60 rows and its 208 dates carry 12,480. Each (date, ticker) pair appears 2 times by design (6,240 repeated pairs) and each (date, ticker, model) key once (0 repeated keys), so the repetition is the models rather than a duplicate-row or join defect. The file covers 54 distinct tickers over 2017-08-09 to 2026-07-01.

Three distinct periods appear on this page. The Deployability table covers the backtest window, the longest of the three. The prediction file above covers a shorter range, because it begins after a 252-date warm-up and ends where a 10-day forward label stops being observable. The signal date under Latest diagnostics is the last date in the dataset and is later than both, because a signal needs no realized forward label. Each is reported against its own period and no figure is carried between them.

Limitations

  • A one-feature momentum baseline beats every trained model — 0.002264 against 0.001992 for elastic_net, before cost on matched dates.
  • No optimizer mode beats the VN30 benchmark. Compounded as the overlapping-tranche portfolio the strategy would actually trade, every mode finishes behind the equal-weight VN30 benchmark after costs.
  • Margins are thin. The most conservative portfolio configuration does not clear cost, at a diagnostic Sharpe of −0.042, and a 95% bootstrap interval on mean active return of [−0.002056, 0.000462], which spans zero.
  • Concentration reduces performance, which is what a weak ranking signal looks like.
  • Foreign buy/sell features are not promoted. Pre-registered test, paired block bootstrap on daily Rank IC over 222 non-overlapping signals: mean difference −0.002608, 95% CI [−0.013314, 0.008297]. The interval spans zero and the point estimate is negative. The promotion rule was fixed before the result was seen: promote only if the interval excludes zero.
  • Features are fitted in raw levels while the target is demeaned against the constituent benchmark, and no within-date standardisation is applied. Whether that specification handicaps the models is untested.
Multiple comparisons. The training window is chosen by measuring five values against the same history, on top of three horizons, five ablation configurations, four optimizer modes, two execution modes and five foreign-flow feature sets tested against it. Nothing here corrects for the number of comparisons, and the intervals that exist (12 strategy and baseline rows of benchmark_results.csv, plus the foreign-flow test) are each marginal rather than family-wise. Rank IC, hit rate, and every per-horizon and per-ablation figure on this page is a point estimate with no interval at all. This is a statement about the configurations measured here, not about the VN30 market.

Reproduce

Setup

This page was built with Python 3.14.5, the version the test suite runs on; version ranges are pinned in requirements.txt.

git clone https://github.com/nguyenhuygiabao/vn30-alpha-research.git
cd vn30-alpha-research
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS and Linux
python -m pip install -r requirements.txt

Rebuild

Run from the repository root, since scripts read paths relative to it. On Windows, py works in place of python.

python scripts/run_full_pipeline.py          # every pipeline table, then this page
python scripts/diagnose_training_window.py   # the training-window sweep
python scripts/diagnose_tranche_drawdown.py  # Deployability, the daily series and the charts
python scripts/describe_modeling_dataset.py  # the dataset and feature-group tables
python scripts/build_report_page.py          # this page alone, from reports/tables/
python -m pytest -q

Scripts: scripts/run_full_pipeline.py · scripts/diagnose_training_window.py · scripts/diagnose_tranche_drawdown.py · scripts/describe_modeling_dataset.py · scripts/build_report_page.py.

Data access

The FiinQuant data is not in the repository. data/raw/ and data/processed/ are excluded by .gitignore, so a clone can rebuild this page from the committed tables and run the tests that read them, but cannot rerun the pipeline. Rebuilding from raw data needs a FiinQuant account: install the vendor's FiinQuantX wheel in its own environment as the README.md describes, set FIINQUANT_USERNAME and FIINQUANT_PASSWORD, and run scripts/download_fiinquant_history.py, which writes the canonical files under data/raw/fiinquant/canonical/. FLC and ROS raw prices need a vendor archive export as well, imported by scripts/import_fiinquant_archived_history.py.

This page is generated by scripts/build_report_page.py from reports/tables/ on every pipeline run, so its figures cannot drift from the tables. Full detail in reports/final_results.md and reports/methodology.md.
